# DReport v0.1

DReport is a standalone, local-first macOS application for recording,
organizing and reporting work.

Its primary purpose is to preserve both:

1. the structural context of work;
2. the chronological history of what happened.

The application must remain generic and publicly usable. User names,
organizations, filesystem paths and other personal information must never
be embedded into application defaults.

## Work structure

DReport separates Themes from individual work items.

Themes may themselves be hierarchical.

A Theme contains work items.

Work items may contain other work items to arbitrary depth.

There is no fixed maximum nesting level.

Supported work item types are:

- Task
- Note
- Activity

Tasks may have one of these statuses:

- To Do
- In Progress
- Completed

Notes and Activity entries do not require a status.

A work item may have:

- title and text;
- text only.

## Chronology

The hierarchy of work is independent from chronology.

DReport records timestamps including:

- Created
- Updated
- Scheduled
- Started
- Completed
- Logged

Status changes and other significant modifications are recorded as
history events rather than only storing the final state.

## Entities

DReport maintains a separate model describing for whom, with whom or in
relation to whom work is performed.

Entity types are:

- Organization
- Group
- Person

Organizations may be nested inside other organizations.

Groups may exist within organizations or independently.

People may exist within organizations/groups or independently.

An entity may have more than one membership. This allows, for example,
one person to belong to multiple groups or organizations at the same
time.

The organizational/entity structure is therefore not restricted to a
single-parent tree.

## Work-to-entity relationships

A work item may be linked to one or more entities.

Initial semantic roles are:

- For
- Requested by
- With
- Assigned to
- Related to

Relationships may be inherited by descendant work items.

A descendant may add or override contextual relationships.

## Main views

Initial navigation contains:

- Today
- To Do
- In Progress
- Completed
- Timeline
- Themes
- Organizations
- Groups
- People

A later global Search view will search titles and textual content.

## Today

Today is not merely a list of tasks scheduled for the current date.

It must eventually distinguish between:

- work scheduled for today;
- activity actually performed today.

## Export and reporting

Export is a core feature, not an afterthought.

Any work item must eventually be exportable together with:

- descendants;
- notes;
- activity entries;
- status;
- entity relationships;
- dates and times;
- chronological history.

DReport must also support date-based reports such as a Daily Report.

The data model must allow future exports including:

- Markdown
- JSON
- HTML
- PDF

Portable export ensures that user data is never locked into DReport.

## Storage

The first version is local and offline.

No account or server is required.

The persistence layer must remain separated from the domain model so that
future synchronization can be added without redesigning the work model.
